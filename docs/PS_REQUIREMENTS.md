# DENTRACE — College Problem Statement & Compulsory Requirements Traceability Matrix

> **DOCUMENT ID:** DOC-REQ-001  
> **STATUS:** AUDITED & VERIFIED (LEVEL 0.5)  
> **REVIEW DATE:** 2026-10-18 (Level 0.5 Audit Completed)  

This document formalizes every compulsory outcome mandated by the College Problem Statement, detailing the architectural specification, planned implementation, and verification test for each requirement.

---

## 1. Requirements Traceability Matrix

| # | Compulsory Outcome | Architectural Specification | Planned DENTRACE Implementation | Verification & Acceptance Test | Status |
|---|---|---|---|---|---|
| **R1** | **Accepts panoramic dental X-rays (OPGs)** | Ingestion pipeline supporting 2D OPGs in standard raster formats (PNG, JPEG, BMP, DICOM if converted). Must validate image aspect ratio (typically 1.8–2.4:1), minimum resolution, and contrast. | `backend/api/main.py` (`POST /api/analyze`) and `frontend/app.py` upload tab. Quality screening module in `backend/pipeline/quality.py`. | Unit test with valid/invalid OPG resolutions, aspect ratios, corrupted headers, and zero-byte files (`tests/test_intake.py`). | Planned (Level 1) |
| **R2** | **Detects 5 key dental anomalies (caries, periapical lesions, impacted teeth, bone loss, root canal failures)** | Multi-head or two-stage detector trained on verified dental labels. Caries, deep caries, periapical lesions, and impacted teeth are detected via segmentation. Root canal failure is supported as **"Partly: rule-based suspected-failure flag; RCT detector not in default flow; accuracy not measured"**. Alveolar bone loss is **"Not automatically detected"** (requires clinician-entered chairside probing depth). | `ml/` YOLOv8-seg / detection pipeline; composite clinical rule for suspected endodontic failure (RCT + periapical radiolucency). Secondary candidate `8024.onnx` provides RCT segmentation on demand. | Per-class sensitivity, precision, mAP50, and clinical confusion matrix on isolated test split (`tests/test_model_eval.py`). | Verified & Hardened (Level 6–10) |
| **R3** | **Multi-pathology instance segmentation with detection-only fallbacks** | True pixel-level segmentation polygons for classes where pixel masks exist in training data. Explicit bounding-box detection fallbacks for classes without true pixel masks. Never present bounding boxes as segmentation masks. Level 0.5 audit proved DENTEX includes true polygon segmentations for caries, deep caries, periapical lesions, and impacted teeth (averaging 12 vertices/polygon). | `backend/schemas/finding.py` (`annotation_modality` field: `instance_segmentation` vs `detection_bounding_box` vs `polyline`). UI legend explicitly labels mask vs box. | Automated schema validator verifying that bounding-box predictions are flagged as `detection_bounding_box` and rendered without synthetic poly contours (`tests/test_schemas.py`). | Verified & Planned (Level 1) |
| **R4** | **Identifies individual teeth and maps to FDI numbers (11–48)** | Localization of individual permanent teeth in FDI two-digit notation. Spatial association of anomaly masks/boxes to host teeth via maximum area overlap ratio ($>15\%$). Topological rules: max 8 teeth per quadrant, no duplicate numbers. Verified pretrained candidate `abychkov/dental-fdi-detection` (32-tooth FDI ONNX model, 4,000+ training OPGs). | `backend/pipeline/matching.py` implementing `post_process_fdi_teeth()` and `match_finding_to_tooth()`. Standalone tooth localization head adapted from `abychkov` or fine-tuned on DENTEX `quadrant_enumeration`. | Unit tests covering quadrant bounding, deduplication retaining highest confidence, and geometric overlap matching (`tests/test_matching.py`). | Verified & Planned (Level 1) |
| **R5** | **Lightweight YOLOv8-Seg / MobileNetV3-U-Net trained with PyTorch** | Parameter-efficient convolutional/transformer architecture suitable for edge CPU deployment and local GPU fine-tuning (4 GB VRAM budget). | `ml/train.py` using PyTorch / Ultralytics with batch size $\le 8$ locally or Google Colab T4 for full epoch runs. | Verification of model architecture parameter count ($<30\text{M}$ params) and reproducible training loss convergence. | Planned (Level 2) |
| **R6** | **ONNX Runtime export with INT8 quantization & sub-50ms CPU benchmark** | Conversion of PyTorch `.pt` to ONNX (opset 17, `ir_version=10`) with static/dynamic INT8 quantization. Benchmark host CPU latency (p50, p95). Never promise sub-50ms prior to measurement. | `ml/export_onnx.py` and `benchmarks/benchmark.py` running onnxruntime with intra-op multi-threading. | Automated benchmark script producing reproducible latency table and markdown report with real measured numbers (`benchmarks/benchmark.py`). | Planned (Level 3) |
| **R7** | **Local quantized Phi-3-Mini or Qwen2.5-3B-Instruct via Ollama** | Offline inference using local Ollama daemon on `127.0.0.1:11434`. Pydantic JSON schema format constraint. Low temperature ($0.1$) to prevent hallucination. | `backend/llm/ollama_client.py` using `qwen2.5:3b-instruct` (primary) or `phi3:mini` (fallback). | Integration test verifying local HTTP communication with Ollama, schema compliance, and offline fallback template triggering (`tests/test_ollama.py`). | Planned (Level 4) |
| **R8** | **Structured, editable, evidence-grounded pre-auth narratives with ADA CDT references** | Pre-auth narrative generation restricted strictly to observed facts. Uses small demo CDT mapping in `config/cdt_demo.json` marked "demo only, verify against ADA CDT set". Downstream bidirectional faithfulness validation. | `backend/rules/rule_engine.py`, `backend/llm/faithfulness.py`, and `backend/llm/fallback_template.py`. | Bidirectional faithfulness test verifying rejection of hallucinated teeth/conditions and 100% pass on faithful output (`tests/test_faithfulness.py`). | Planned (Level 4) |
| **R9** | **FastAPI backend and Streamlit clinical UI** | Decoupled client-server architecture. RESTful API exposing health, analysis, narrative, and PDF endpoints. Streamlit dashboard with custom components. | `backend/api/main.py` and `frontend/app.py`. | End-to-end API contract tests using FastAPI `TestClient` (`tests/test_api_endpoints.py`). | Planned (Level 5) |
| **R10** | **Color-coded findings, interactive odontogram, PDF claim pack export** | Colorblind-safe Okabe-Ito palette paired with text labels. Interactive HTML5 canvas for hover/click. Clickable FDI odontogram. ReportLab 2-page claim pack PDF with empty dentist signature block. | `frontend/components/canvas_viewer.py`, `frontend/components/odontogram.py`, and `backend/reports/pdf_generator.py`. | PDF generation test verifying byte header `%PDF-`, non-trivial size, disclaimer inclusion, and signature block (`tests/test_pdf.py`). | Planned (Level 5–6) |
| **R11** | **Local-only execution with zero external AI API leakage** | Strict localhost network binding (`127.0.0.1`). Streamlit telemetry disabled (`gatherUsageStats = false`). No third-party cloud AI egress. | `config/settings.json`, `.streamlit/config.toml`, and socket boundary enforcement. | Network isolation verification test asserting zero outbound connections during full pipeline execution (`tests/test_privacy_egress.py`). | Planned (Level 7) |
| **R12** | **Clinician confirmation required; no autonomous diagnosis claims** | Prominent persistent notice: *"Draft for dentist review. Not a diagnosis."* on every UI tab, JSON payload, and exported document. Clear disclaimer of regulatory status. | Injected into all Pydantic schemas, UI headers, and PDF templates. | Schema validation test ensuring `disclaimer` field is immutable and present in all outputs (`tests/test_compliance.py`). | Planned (Level 1) |

## 2. Priority Rule
**Mandatory College PS Core Features First:** All bonus or experimental features (advanced vision-language grounding, CBCT volumetric extensions, EHR bridge) are strictly deferred until requirements R1 through R12 are fully implemented, benchmarked, and verified by automated tests.
